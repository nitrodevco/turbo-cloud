# Every setting of WiredConfig, WiredChestConfig and RoomConfig, each with why a hotel may change it
# (ConfigAllowlistTests). Turbo ships Habbo's behaviour; a setting is for a hotel's own choice, not
# for keeping an older behaviour or tuning one of Habbo's timings. A new property needs a line here,
# and the line says which kind it is:
#   policy  a hotel's own choice: rights, economy, a feature on or off
#   limit   a bound on a room's or player's work or abuse, sized to the hotel's machines
#   data    the hotel's own ids, names or assets
#   client  must equal what the hotel's client offers (an editor bound, a client variable)
#   engine  server work (ticks, flushes, batches, timeouts); nothing a player sees
#   legacy  one of Habbo's values kept as a setting before this list: not a policy; remove it
#           (hard-wire Habbo's value) when its code is next touched, never add one
